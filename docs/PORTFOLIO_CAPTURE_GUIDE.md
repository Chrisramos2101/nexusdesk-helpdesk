# Portfolio Screenshot Capture Guide

Screenshots are intentionally not committed automatically because they should show the final live build and must be reviewed for secrets/private information first.

Recommended captures:

1. Public login page
2. Admin dashboard with synthetic tickets
3. Ticket detail / notes / assignment workflow
4. User-management page with synthetic users
5. Knowledge-base page
6. Audit/security dashboard
7. Mobile browser dashboard

## Before capturing

Hide or avoid:

- email addresses you consider private
- passwords
- API keys
- database connection strings
- reset tokens
- MFA codes
- Render environment-variable values
- Brevo API-key screens

## Suggested dimensions

Desktop:

- 1440×900 or similar

Mobile:

- normal phone portrait orientation

## GitHub presentation

If you later add screenshots, place them in:

```text
docs/screenshots/
```

Then add a short `## Screenshots` section to the root README.

Do not add screenshots merely to fill space. Use only images that clearly demonstrate useful product behavior.
